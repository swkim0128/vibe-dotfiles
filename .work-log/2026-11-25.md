## 🖥️ 개인컴

### 메인 TUI 재실행과 prefix+i 관리 메뉴

- 사용자 요청으로 메인 `wA:t1` 아래 TUI를 `wA:p3G`로 다시 실행했다. 기존 TUI가 없던 상태여서 `bar ensure --tab wA:t1 --parent-pane wA:pZ`로 생성했으며 결과는 restored, 외곽9행이다. 부모 공식 대화 정보가 없어 identity_unverified와 목록 조회 미확인은 남아 있다.
- `prefix+i`·`prefix+ㅑ`를 ‘재시작 / 닫기’ popup 메뉴로 변경했다. 새 `bin/herdr-bar-control.sh`는 호출 위치를 대조하고 실제 실행 경로와 view 인자로 TUI를 식별한다. 재시작은 기존 bar ensure 경로를 사용하며 없으면 생성한다. 닫기는 현재 탭의 TUI 하나만 대상으로 하고 중복 TUI와 메뉴 취소는 변경하지 않는다.
- 설치 링크를 manifests/common.conf에 추가하고 개인컴의 해당 링크 하나만 배포했다. Herdr reload-config는 diagnostics=[], status=applied다. Codex 프로세스·훅 신뢰·큐 DB는 변경하지 않았다.
- 보이는 CLI 실행 셸에서 ShellCheck가 진단 없이 완료됐고 git diff --check는 종료0이다. 실제 단축키·선택·취소·닫기 회귀와 부모 공식 연결 복구는 미검증이다. 새 테스트나 Rust 변경·재빌드·전체 설치는 하지 않았다.
- 부모 공식 대화가 없는 TUI에서도 현재 TUI scope가 일치하면 소유자 인자 없는 공개 `vibe queue list --all`로 목록·건수·상세 기록을 읽도록 `herdr/hud.py`와 Rust 표시 경로를 수정했다. `조회 전용(부모 미연결)`을 표시하며 thread·binding을 생성하지 않는다. private HUD 조회와 부모용 사이드바 갱신을 하지 않고 요청·발신·완료 확인에는 기존 공식 부모 검증을 유지한다. 구현 완료·미검증이며 빌드·배포·화면 확인은 메인에게 인계했다. 테스트 작성·실행과 커밋·push는 수행하지 않았다.
- 메인 후속: 최종 Rust 소스를 보이는 dotfiles 셸에서 release 빌드해 4.11초에 완료했다. 기존 ensure --relaunch 결과 wA:p3G→wA:p3H로 교체됐고, 공개 큐 9건·대기7건과 요청 행 표시를 확인했다. 조회 전용·부모 미연결 표시는 유지하며 신원 복구나 쓰기 검증 통과로 보고하지 않는다. 편집 훅의 Python 구문 검사 receipt는 passed이고 양 저장소 diff --check는 종료0이다. 신규 회귀 테스트와 실제 실행 버튼 거부 시험은 하지 않았다.
